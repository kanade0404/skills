# ADR

このリポジトリの設計の決定（Architecture Decision Record）を置く。

1 つの決定を 1 つのファイルに書き、ファイル名は `YYYY-MM-DD-<kebab-case のスラッグ>.md` にする。日付は ADR を書いた日にする。ただし、Phase 0 のように、ある段階の土台を定める ADR は、いっしょに合意した関連する決定を 1 つのファイルに束ねてよい。以降の決定は、1 つずつ別のファイルにする。束ねた決定のうち 1 つを改める ADR は、束ねたファイルの名前と決定の番号を引く。番号は振らず、ほかの文書から ADR を指すときはファイル名で引く。

この名前にするのは、共有の連番を持たないようにするためだ。複数の worktree で ADR を同時に書いても番号が衝突せず、古い順は日付で分かる。同じ日付とスラッグが重なったときは、スラッグを変える。

決定を改めるときは元のファイルを書き換えず、新しい ADR を足して、元の ADR の状態を「置き換え」にする。
